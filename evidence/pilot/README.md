# 真实试点证据目录

此目录只提供空白模板，不含学生数据。不得提交姓名、手机号、住址、人脸、身份证号等个人信息；`student_id` 必须使用无法反推身份的随机编号。

## 使用顺序

1. 复制两个模板到学校批准的受控位置，并完成授权、脱敏和独立复核。
2. 每名学生、每个指标保留一行；同一匿名学生集合必须出现在每个指标中，退出或缺测也必须保留行。
3. 完整配对记录须逐行填写 `pre_assessed_at` 与 `post_assessed_at`（`YYYY-MM-DD`、前测不晚于后测、均在清单的试点窗口内）。完整记录的 `missing_reason` 必须为空；缺失记录两日期均留空，且 `missing_reason` 只能是 `ABSENT`、`WITHDREW`、`TECHNICAL` 或 `OTHER_APPROVED`，不得填写自由文本。
4. CSV 只允许模板声明的 11 列；不要加入姓名、备注、教师评语或任何其他附加列。`student_id` 需使用至少 6 位、同时含字母和数字的随机匿名编号；格式检查不能代替学校侧的不可反推性审核。
5. 只有证据真实、授权完成后，才把清单中的 `dataKind` 改为 `REAL`，并如实填写两个布尔确认项。禁止为了通过检查伪造确认。
6. 运行：

   ```powershell
   node scripts/analyze-pilot-evidence.mjs --input <脱敏数据.csv> --manifest <试点清单.json> --out docs/audit/pilot-evidence-latest
   ```

脚本会校验授权声明、最小化表头、匿名编号外观、学生集合一致性、样本完整性、量表范围、前后测配对及日期窗口、受控缺失记录、试点时长和样本量；结果同时生成 JSON 与 Markdown。任一指标没有可分析的配对样本即失败关闭。单组前后测只能说明本试点中的关联，不能单独证明因果。
