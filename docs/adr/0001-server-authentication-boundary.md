# ADR-0001：本地优先的服务端教师认证边界

- 状态：已接受
- 日期：2026-08-04
- 决策者：项目审查与升级工作流
- 适用范围：Fastify API、编排官 WebSocket、React 教师端

## 背景

系统原有“登录”只把 `isAuthenticated`、教师工号和姓名写入浏览器
`localStorage`。前端路由守卫能够改善界面流程，但不能证明请求者身份：任何人都
可以伪造本地状态并直接调用后端接口；后端也会信任请求体或查询参数中的
`teacherId`。这会使模型密钥设置、长期记忆、学生学情、教研报告和课堂控制等
接口共享同一个无认证信任域。

本项目同时有两个不能互相牺牲的约束：

1. 竞赛现场必须能在单机、无外网、无额外账号系统的环境中一键演示；
2. 一旦监听非回环地址或接入真实学校数据，必须具备服务器可验证的身份、请求
   完整性和默认失败关闭能力。

## 决策

采用“同源 HttpOnly 签名会话 + 双提交 CSRF + Origin 校验 + 教师身份绑定”的
本地优先认证边界。

### 认证模式

- `AUTH_MODE=demo`：只允许服务器内置且公开展示的一个演示教师档案登录。登录
  后仍由服务器签发不可伪造的 HMAC-SHA256 会话；任意工号不能自行成为教师。
- `AUTH_MODE=password`：只允许环境变量配置的教师账号，密码只保存
  `scrypt` 派生摘要，服务器不持久化明文密码。
- 密码模式必须配置至少 32 字节的会话密钥和合法、参数可执行的 scrypt 摘要，否则启动失败。
- 演示模式未配置会话密钥时，每次进程启动生成临时随机密钥。重启会主动使旧
  会话失效，避免仓库内出现共享固定密钥。

### 会话与请求保护

- 会话写入 `pr_session`：`HttpOnly`、`SameSite=Strict`、`Path=/`；生产 HTTPS
  部署可强制 `Secure`。
- CSRF 随机值同时进入签名会话和可读的 `pr_csrf` Cookie。写请求必须提交匹配的
  `X-CSRF-Token`；浏览器同源 Origin 是第二道校验与兼容兜底。
- `/api/health`、`/api/auth/status` 和 `/api/auth/login` 是唯一公开 API；数据库
  健康细节、所有业务 API 与 `/ws/orchestrator` 均要求有效会话。
- 请求顶层 `teacherId` 必须与会话主体一致，否则返回 403。资源本身仍需保持
  路由/服务层的班级、学生和资源所有权校验，不能把这一检查误当成完整 RBAC。
- 当前版本明确采用单教师、本地单租户数据模型。启动时只迁移
  `teacher-demo-001` / `teacher-default` 两个历史原型主体，并扫描所有带
  `teacher_id` / `owner_id` 的持久表；发现第二个非历史主体立即拒绝启动。
- 编排与副驾会话的列表、读取、删除、执行、暂停、恢复、中止和修改均以签名
  会话主体回查所有权，不能只凭客户端提交的 `sessionId` 操作。
- 密码登录按来源 IP 做进程内失败限速；错误响应不区分“账号不存在”和“密码
  错误”，也不回显密钥、摘要或栈。
- 401 表示会话不存在、损坏或过期，前端回到登录页；403 表示已认证但无权访问，
  前端进入权限说明页。禁止继续用 403 页面任意切换本地教师身份。

## 非功能约束

| 维度 | 约束/验收线 |
| --- | --- |
| 可用性 | 回环单机演示零账号基础设施；后端离线时只允许进入已明确标识的本地演示数据路径，不能访问真实 API |
| 安全性 | 会话签名常量时间比较；默认 8 小时、最大 24 小时；写请求 CSRF/Origin 校验；非回环不安全配置启动失败 |
| 隐私 | Cookie 不存模型密钥、班级/学生明细；日志不得记录 Cookie、密码、CSRF 和完整会话令牌 |
| 性能 | HMAC 校验为每请求常数开销；认证状态接口不访问 AI 服务；密码 scrypt 只在登录时执行 |
| 可测试性 | 必须覆盖伪造签名、过期、教师错配、CSRF、限速、注销、重启失效、WebSocket 无会话拒绝 |
| 可运维性 | 密码摘要由脚本生成；环境变量错误在数据库初始化前失败；状态接口只返回模式与公开演示档案 |

## 失败模式与兜底

| 失败模式 | 第一兜底 | 兜底失败后的边界 |
| --- | --- | --- |
| Cookie 被篡改 | HMAC 校验失败，401 | 清除无效 Cookie，要求重新登录；绝不回退为请求中的 teacherId |
| 会话过期 | 401 + 前端清理本地认证缓存 | 保留未提交表单应由具体页面草稿机制负责，认证层不自动重放写请求 |
| 服务重启且使用临时密钥 | 旧会话失效 | 一键重新选择演示教师；不复用可预测固定密钥 |
| CSRF Cookie 不可用 | 合法同源 Origin 可兼容一次 | Origin 也不匹配则 403，不以关闭防护换取成功 |
| 后端完全离线 | 前端进入醒目标识的 DEMO 数据路径 | 禁止声称数据已保存；恢复后必须重新验证服务器会话 |
| 密码暴力尝试 | 失败计数与临时锁定 | 多实例/重启会重置计数；正式公网部署仍需上游 WAF/集中限速 |
| 明文 HTTP 非回环部署 | 安全网络边界校验拒绝启动 | 只能配置 HTTPS 反代 + Secure Cookie，或显式声明受控容器内边界 |
| teacherId 越权 | 全局顶层身份绑定返回 403 | 资源级所有权继续在服务层校验；不能依赖前端隐藏控件 |
| 数据库混入第二教师资源 | 单租户启动门禁拒绝运行并报告受影响表/数量 | 为教师使用独立 SQLite；不得自动吞并未知主体或关闭门禁 |
| 会话 ID 横向访问 | 路由从 SessionStore 回查教师主体，403 | 控制动作不会到达 InterventionManager，避免先产生副作用再报错 |

## 备选方案

1. **继续只做前端守卫**：不构成安全边界，否决。
2. **Bearer Token 存 localStorage**：容易被 XSS 读取，且 WebSocket 需要把令牌放入
   查询参数或子协议，泄漏面更大，否决。
3. **立即接入 OAuth/OIDC**：公开部署更成熟，但增加网络、租户配置和比赛现场
   故障点；当前阶段不作为默认方案。未来学校统一身份平台可替换登录端点，同时
   保留后端会话与资源授权层。
4. **为演示账户写入固定密码/固定会话密钥**：会把可复用凭据带入仓库，否决。
5. **完整多租户 RBAC 数据库**：长期方向正确，但当前没有用户/组织主数据和学校
   身份源。先建立不可绕过的服务器边界与单教师所有权，再以迁移方式扩展。

## 影响

正向影响：直接 API、WebSocket 和浏览器界面共享同一个服务器身份真相源；现场
演示仍可一键登录；非回环部署具备明确的安全门槛和可审计配置。

代价与剩余风险：演示模式证明的是“被允许的演示档案会话”，不是现实教师身份；
进程内注销/限速不等于分布式会话基础设施；当前失败关闭的单租户门禁也不等于
校园多租户 RBAC。任何涉及多教师或真实学校数据的公开部署仍需 tenant 主数据、
逐资源授权、TLS、学校身份源、集中会话撤销、审计保留策略和授权渗透测试。
