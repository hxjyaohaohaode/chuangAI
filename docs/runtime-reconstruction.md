# 运行内核重构：实现、验收与边界

更新：2026-09-27。工作分支：`refactor/verified-foundation-20260926`。本文描述当前源码；最终回归状态以对应提交的 GitHub Actions 日志和 artifact 为准。

## 1. 产品与交付范围

诗脉·启明 PoeticRealm AI 是面向小学古诗词教学的教师端系统。现有业务围绕备课、命题、课堂活动、作答与批改、学情诊断、创作反馈和教研报告展开；诗词星图、文化语境和 Agent 可观测界面提供关联入口。当前后端的部署边界仍是单教师本地租户，而不是已经完成的学校多租户平台。不存在已经交付的完整学生自学端。

本分支实际替换的是执行状态机与数据交接内核，并改造中央调度、任务介入、会话检查点访问和前端查询缓存边界；同时统一已检查的 Node 入口、修正部署敏感默认配置，添加针对性测试与完整现有回归命令。**它不是全站所有页面、所有 Agent、所有数据模型已经从零重写的声明。** 原有功能入口和历史证据保留，不用删掉复杂功能的方式声称完成升级。

本次从 GitHub 分支及主分支合并结果复核源码，并逐条检查 PR #2 的自动审查意见。旧审计材料不作为本次运行证据。

## 2. 实际发现与处理

| 缺陷或风险 | 修改 | 对应验证 |
|---|---|---|
| 原 DAG 对嵌套 input/result 只做浅复制，外部可修改调度状态关联数据 | 有预算的递归数据复制；输入、快照、结果与条件评估之间隔离 | 嵌套对象、Buffer、结果 Map 和条件回调变异测试 |
| 原完成/失败方法没有严格阻止非法终态改写 | 状态转换检查；运行修订号；过期尝试结果不落入新尝试 | 未执行先完成、终态复活、暂停修改后旧结果迟到 |
| 原上游修改只重置一个节点，后继可能继续使用旧结果 | 先检查整条后继链，再统一失效所有传递后继；拒绝修改仍有运行后继的图 | 三层依赖、独立分支保留、原子拒绝 |
| 带 condition 的节点在前置失败后可能永远 pending | 依赖失败沿拓扑顺序传播；condition 不能绕过失败前置 | 条件节点与普通下游均进入终态 |
| Promise.allSettled 按批次等待，无关慢节点阻塞就绪后继 | 工作保持型调度，任一任务完成即重新计算可执行任务 | 快分支后继在独立慢分支结束前执行 |
| 没有明确的上游结果字段绑定；仅写 dependencies 不等于数据联通 | 新增 `$from` 引用；只有显式直接依赖可提供数据；字段缺失失败关闭 | 引用成功、未声明依赖、无产物、非法路径 |
| 会话被重复执行时可复用并替换上下文 | 同会话执行期间拒绝重入；任务标识跨会话歧义时拒绝介入 | 同会话双执行与身份替换被拒绝 |
| 共享 Agent 并发与大量就绪任务缺少统一准入 | 全局最多 8 个调用、每会话最多 4 个在途任务、同一 Agent 实例串行、排队上限 256 | 同 Agent 串行、不同 Agent 并发、取消排队、队列上限 |
| 取消/暂停后旧调用或任务列表残留 | 取消将运行、等待和暂停任务置为终态；修订令牌使迟到写入无效 | 暂停会话取消、旧结果迟到、槽位回收 |
| UI 状态订阅回调异常可干扰任务结果 | 观察回调与 Agent 成败隔离，留下无载荷警告 | 观察回调抛异常，正确结果仍成功 |
| 持久化会话读取执行 delete + set，读操作产生删除窗口与写放大 | SQLite 读取不再删除/重写；更新直接使用已有事务 upsert | 完整既有会话/数据库回归；内存 LRU 保留 |
| 全局查询缓存跨教师、角色、班级复用 | 认证主体和班级变化时切换独立 QueryClient，并清除退休缓存 | 教师切换、班级切换、退出、迟到响应、变更名称 |
| Render 蓝图含个人信息和固定密码验证值，真实部署默认播种演示数据 | 蓝图只保留无值的手机号和密码摘要输入；正式模式禁用演示身份回退及公开演示摘要；关闭默认演示数据播种 | 配置与认证测试；生产控制台与实际凭据轮换仍须单独核验 |
| 应用、生产入口与 E2E 分别写死旧 Node 版本 | 统一为 Node 24 契约，冻结 pnpm 与依赖锁文件；不是仅修改 package.json | Node 24 实际构建、路由与生产同源浏览器测试 |

上表的修改以当前提交的源码、GitHub Actions 日志与 `runtime-evidence-*` artifact 核验。CI 不修改源码、不自动向分支提交或推送；失败和取消的运行不能当作通过证据。

## 3. 执行与数据合同

`runtime-data.ts` 只传递数据，不执行引用字符串。载荷递归深度上限 24、访问项上限 50,000、默认 UTF-8/二进制累计预算 2 MB。循环引用、访问器、非常规原型、危险属性名和非有限数值被拒绝。复制边界不是完整的数据脱敏方案；真实学生数据仍须遵守原有身份、班级和授权约束。

引用示例：

```json
{
  "id": "report",
  "agentId": "brush.report",
  "dependencies": ["diagnosis"],
  "input": {
    "classId": "the-authorized-class-id",
    "diagnosis": { "$from": { "taskId": "diagnosis", "path": [] } }
  },
  "status": "pending"
}
```

`path` 是属性名数组，空数组表示整个成功产物。不能引用未声明的任务、原型属性或不存在的字段。输出仍由各 Agent 自身的输入/输出契约检查；本次没有替换全部业务 Schema，也没有实现跨任意任务的隐式“猜测补全”。

失败依赖会使后继跳过。内部 condition 回调只在前置全部成功后评估，不能充当错误恢复。需要错误补偿时，应显式设计补偿任务与其数据合同，而不是在已有条件注释中假设它存在。HTTP 计划中的条件说明字符串不被执行为 JavaScript。

## 4. 并发、暂停与取消

准入分为每会话上限和共享 Agent 上限，避免大图突然发出无限量模型请求。排队请求响应 AbortSignal，取消会删除相应队列项。节点调用超时从获得共享 Agent 准入后起算；队列等待受会话取消和队列容量约束。

对不遵守取消信号的服务商调用，系统不能承诺远端立即停止计费。执行内核停止等待并阻止迟到结果写回，但占用的共享 Agent 槽位只有在底层调用实际结束时才释放，避免同一有状态 Agent 被重叠复用。底层调用永久悬挂仍可能耗尽容量，必须由网络层超时、运维告警和受控重启共同治理。本次未实测真实服务商的取消和计费行为。

教师修改会使传递后继全部失效，这是必要的行为变更，不是“每个已完成结果都永久有效”。运行中的后继存在时，修改被拒绝，不偷偷接受半修改状态。重启恢复仍沿用原有“标记中断、由教师确认重新执行”策略，不自动重放可能带副作用的任务。本次没有声称实现分布式 exactly-once。

## 5. 前端数据一致性

查询缓存以是否登录、用户 ID、角色、班级 ID 的 JSON 元组为隔离键。新主体使用新的 QueryClient；旧请求即使迟到也不能填入新主体缓存。改显示名不触发无谓重建。查询默认 30 秒 staleTime、10 分钟缓存回收，恢复网络和窗口聚焦时允许刷新。部分客户端错误不自动重试；写操作不自动重试。

这只解决查询层的一类跨上下文风险，不代替后端权限控制、其他 Zustand/IndexedDB/localStorage 的逐项隔离审计，也不表示全部前端已经重做。已有 12 个主导航模块仍保留。

## 6. 运行与验证

参考运行时 Node.js 24.21.0；允许范围 `>=24.11 <25`。pnpm 10.34.5。切换 Node 主版本后重新按锁文件安装，不能复用旧 Node 构建的 better-sqlite3 二进制。不要复制旧工作目录里的 node_modules、日志、数据库、真实学生数据或密钥到发布目录。

```bash
corepack enable
corepack prepare pnpm@10.34.5 --activate
pnpm --dir backend install --frozen-lockfile
pnpm --dir frontend install --frozen-lockfile
pnpm --dir backend build
pnpm --dir frontend build
pnpm --dir backend test
pnpm --dir frontend test
pnpm --dir backend test:routes
pnpm --dir backend test:closed-loop
pnpm --dir frontend exec playwright install --with-deps chromium
pnpm --dir frontend e2e:password
```

独立终端分别执行 `pnpm --dir backend dev` 和 `pnpm --dir frontend dev`。按根目录 `.env.example` 配置后端环境；真实数据必须使用服务器密码认证，不以浏览器缓存作为身份凭据。

Actions 直接检验签入仓库的源码。`verify-runtime-refactor.py` 对安装、构建、单元测试、路由、教学闭环和生产同源浏览器测试逐条记录退出码与完整日志，并在 `runtime-evidence-*` artifact 中保存 `summary.json`、原始日志和源码 SHA-256 清单。任何失败均使门禁失败；源码在测试中发生变化也会失败。不要把旧报告或取消的运行混同最新发布证据。

## 7. 必须保留的安全边界

原 Render 蓝图的固定密码验证信息已经进入公开历史。本分支删除它不等于历史消失，也不等于已部署服务自动轮换。已经按旧蓝图上线的服务应立即设置全新高强度密码、更新密码摘要并撤销旧会话；如有个人环境字段，须在控制台检查清除。不要把新密码或摘要提交进仓库。未改写 Git 历史、未操作生产账户或生产数据库。

Root `render.yaml` 与已检查的 Render 启动入口改用 Node 24；真实 Render 部署、Docker 镜像及所有打包白名单仍须单独验收，不能只凭本地或 CI 单元测试放行。教师手工审核、诗文来源复核、真实试点评估等外部门禁未删除、未伪造。
