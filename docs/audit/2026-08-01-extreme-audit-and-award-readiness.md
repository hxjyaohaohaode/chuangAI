生成日期：2026-08-01

> 2026-08-09 收口复核：以下运行与供应链数字按最新审计证据刷新；Node `>=20.19 <21` 与 pnpm 10.34.5 已在隔离 Node 20.20.2 环境完成冻结安装、原生 SQLite 编译和运行时验证；实体比赛机仍须按相同版本现场复验，外部真实试点、逐首内容签名和凭据轮换仍未替代。

## 一、先给结论

项目已经从“功能数量很多的 AI 教学原型”升级为“可生产构建、可离线演示、接口闭合、故障可降级、证据可复核的古诗词教学智能应用”。但现在不能真实承诺全国一等奖或赛道前 1%：技术完整度已接近提交要求，最大未闭环项是**真实学校/教师/学生使用证据及可验证成效**。任何虚构用户数、提分率、课堂案例或获奖概率都会直接违背官方真实性要求，并可能一票否决。

当前最优战略不是继续无边界增加功能，而是聚焦一条评委能在 8 分钟内看懂、相信、记住的闭环：

> 教师备课 → AI 分层命题 → 课堂实时调度 → 多模态批改 → 六阶诊断 → 个性化干预 → 学生创作再迭代 → 教师反馈驱动系统进化。

## 二、为什么用户会提出这项任务

从项目状态与要求可推断，真实担忧不是“少一个按钮”，而是：功能庞大但可能存在隐藏断链、漂亮界面与真实能力不一致、比赛材料无法证明技术价值、演示现场一旦断网或模型失败就失控。目的在于把研发视角切换为最高奖评审视角：每个亮点必须可演示，每项宣传必须有证据，每个失败必须有退路，所有复杂性最终服务于真实教学问题。

这是基于官方评分结构、代码/接口/测试事实与现有材料作出的推断，不是对用户心理的确定事实。

## 三、官方约束与项目方向

官方评分共 100 分：价值导向 10、AI 开发与应用 10、真实问题 20、易用性 20、开源 10、真实使用 10、创新 10、完整性 10。报告不超过 3000 字，视频不超过 8 分钟，建议结构为 2 分钟痛点、5 分钟实操、1 分钟总结；视频需 MP4、不得出现人脸、AI 内容需标识，原创与第三方归属必须清晰。

项目最合适的方向是“小学古诗词教—学—评—创一体化异构多智能体应用”，而不是通用聊天机器人。原因是当前最强资产已经集中在古诗词知识图谱、布鲁姆六阶、教师可控课堂、多模态识别、诊断处方、创作迭代和反馈进化；继续横向扩张会削弱真实问题、易用性和完整性得分。

## 五、本轮已经修复/升级的核心问题

1. 补齐“创作—AI 多维批改—反馈再创作”教师端闭环，DEMO 样例只在空库时内存合成，明确标注不是学生真实数据、AI 结果或效果证据。
2. 修复前端真实断链与方法错误，包括进化预测 fallback、文化意象 AI 刷新、报告与工坊导出契约。
3. API 审计器扩展到全部前端 TS/TSX，支持动态模板和字符串拼接；17 个间接/管理/兼容端点逐项建账。
4. 路由冒烟从依赖人工启动 3002 改为一键隔离运行，并补齐编排官 REST 与 WebSocket。
5. 关键覆盖率从 48.73%/52.18% 的门禁失败提升到语句 97.04%、行 97.49%，新增真实内存 SQLite、检查点恢复与 OpenAI SDK 契约测试。
6. 首包按项目自设 120KB 门禁精确计算，拆分扩展图标、查询 Provider 与命令面板，禁止大型依赖 preload；不把内部工程预算表述为赛事官方阈值。
7. 去除多处外部可变状态的非空断言，Canvas/空数组/竞态均有显式守卫。
8. DEMO TTS 返回合法 WAV；AI、规则、DEMO、真实数据的标识不再混用。
9. 新增真实试点数据分析门：授权/脱敏声明、匿名编号、量表、配对样本、缺失值、样本量与 95% CI 失败关闭；单组前后测明确不作因果结论。
10. 新增逐首古诗内容哈希与来源验收门；内容变化自动使旧结论 `STALE`，未签字时前端明确显示“待逐首复核”。普通审计不再覆盖人工填写的来源/签字工作表，表头、诗篇身份或哈希不一致时保留原件并失败关闭；只有显式 `--reset-review-template` 才会在新模板前写出私有备份。AI 拼音、译文、生字和讲解缓存同步绑定版本与完整教学输入指纹，避免原文或人工教学上下文已变而仍返回旧 AI 内容；即使 JSON 字段完整，也要在逐行覆盖、拼音字数、生字归属和修辞例句原文回溯全部成立后才会缓存。
11. 新增基于 npm 官方注册表的生产依赖审计；镜像站不支持 audit 时明确失败，不把“查不到”写成“零漏洞”。

13. AI 副驾从单一聊天升级为教师可控任务应用：计划先预览、可修改，批准后才执行，并支持暂停、恢复与中止；浏览器回归使用确定性模拟契约验证全链路，不把模拟结果冒充真实模型效果。

32. 封闭供应商文本/JSON 响应边界：设置页连通性检测的 15 秒超时现在覆盖 DNS、连接、响应头和受限正文消费全过程，错误正文最多 64KiB，DeepSeek/MiMo/DashScope 探测均禁止重定向；Wan API 响应要求 JSON MIME、声明与实际正文最多 1MiB，并禁止重定向。无界 `res.text()`/`response.json()` 已移除；返回教师前还会精确移除当前 API Key、常见 `sk-/ak-` 令牌及 PII。错误页、超大/流式正文、无效 JSON、凭据回显与 30x 均明确降级，不让设置页或生图工作流挂死或反向泄密。
33. 封闭生图缓存并发与崩溃一致性：同一缓存 key 的并发生成经单航班合并为一个 Promise，避免重复模型调用和扣费，失败后释放 key 允许重试；WebP 和 `index.json` 均改为目标同目录独占临时文件、写入、`fsync`、原子替换，失败只清理本次 UUID 临时文件并保留旧目标。不同 key 并发完成时重新读取最新索引再合并，避免旧快照覆盖已完成记录；Windows 实机专项测试验证创建、覆盖、无临时残留、同键合并和失败重试。
34. 收口运行时恢复边界：SqliteMap 的索引查询只接受配置白名单，容量必须为正安全整数，写入与 LRU 淘汰在同一 SQLite 事务内完成并等待短暂写锁竞争；长期记忆容量参数同样正数校验；限流信号量的超时等待通过 AbortSignal 从 FIFO 队列移除取消 waiter，避免幽灵请求吞掉后续并发槽位；课堂认知监测/报告保留定时器与 DanceStage 回看保留定时器在关闭时全部清理，DanceStage 关闭后拒绝旧引用写入并允许热重载重建，同一课堂不会重复启动监测循环；前端重构顾问的 DEMO 流式定时器由 ref 统一清理并覆盖完成、中断、重试和卸载；认证状态、登录和注销请求统一由 10 秒认证超时包住 fetch 与 JSON 正文，外部 `AbortSignal` 在完成态解绑；`fetchJSON`、Blob 下载和 TTS 的超时保持到正文消费结束，外部 `AbortSignal` 监听器在所有完成态解绑；10 个 SSE/ReadableStream 消费循环统一按帧间静默 120 秒中止，区分用户主动中止与系统超时并回调可重试错误；编排器节点超时现在同时拒绝等待、`AbortController.abort('node-timeout')` 中止下游 Agent/SDK 并清理监听器；编排器的全局 EventEmitter 监听器、进化引擎和旧广播器在 Fastify `onClose` 解绑，LLM/Agent 结构化日志订阅也显式解绑并清空短期缓存；多个 Promise 超时降级在主 Promise 提前完成时清除计时器，避免高并发下的延迟句柄堆积；重复 SIGINT/SIGTERM 只允许一个幂等关闭流程。
35. 收口外部图数据库资源边界：dashboard、教案和报告的兼容路径在每次请求的成功、超时、异常后关闭临时 Neo4j Driver；诊断与星图模块的共享 Driver 在 Fastify `onClose` 关闭并清空单例，下次实例化不会复用已关闭连接。这样即使 Neo4j 不可用或请求集中超时，也不会把连接池泄漏到比赛进程寿命之外。

## 九、最终判断

优化方向正确：把复杂 AI 技术收束为教师可控、证据驱动、可降级的古诗词教学闭环，符合官方高分项。当前系统技术层面已经能支撑高质量参赛，但**尚不能仅凭代码保证全国一等奖或前 1%**。决定上限的下一步不是再堆功能，而是补齐真实应用证据、专业教师内容验收和 8 分钟叙事压缩。
