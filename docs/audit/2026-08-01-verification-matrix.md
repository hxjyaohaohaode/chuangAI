## 解释边界

- 616 项测试和 97.49% 行覆盖率只证明已配置关键后端范围的自动化情况，不能外推为“246,649 行代码全部被运行覆盖”。
- HTTP 破坏性探测验证端点不会因最小 / 非法输入产生 5xx 或泄漏栈；它不能替代每个业务分支的真实语义验收。
- API 契约验证路径和方法一致；它不能证明所有返回字段在真实外部模型、真实学校数据下永远正确。
- 32 个页面组合已改由 Fastify 生产模式同源托管前端、API 与 WebSocket，证明当前环境下主要页面可打开且无采集到的控制台警告 / 失败；一次并发执行曾因同时构建造成诊断页加载超时，故赛场 SOP 明确禁止并行构建并要求预热。
- 源码静态清单对所有纳入范围的 TS / TSX / CSS / SQL 文件进行了机器扫描，但人工逐行语义理解与动态分支穷尽在有限时间和不可判定性约束下不能诚实宣称“绝对完成”。

## 推荐最终顺序

1. 冻结一个可回滚的参赛版本和离线安装包；
2. 由语文教师进行内容验收并修复阻断项；
3. 完成至少一轮有前后测和教师计时的授权试点；

5. 在比赛目标设备按赛场 SOP 完整走演 3 次，其中至少 1 次主动断网；
6. 轮换本地环境中曾在审查输出里暴露过的模型密钥，再生成最终发布包。
