# 前端体验深度优化与验证记录（2026-08-06）

## 范围与证据边界

本轮不以“视觉上感觉更好”作为结论。先审阅生产密码模式回归生成的桌面、移动端核心页面截图，并以对应 TSX/CSS 源码与实际交互作为修改依据。已覆盖的生产回归范围是 16 条路由 × 2 个视口，共 32 个组合；这证明本轮覆盖的页面可打开、无采集到的控制台警告/失败和页面级横向溢出，不等价于所有真实学校环境下的主观可用性结论。

发现的可复现问题：

1. 教案工坊在尚未选择模板时，桌面右侧只显示一条说明，工作台的大面积有效区域没有提供下一步信息；移动端统计徽章会将“已备教案”拆为逐字换行。
2. 长期记忆治理等连续操作可在右上角堆叠多条成功通知，覆盖教师的首屏可用区域。历史实现只做“完全相同消息去重”，不能处理不同成功消息的突发队列。
3. 智能批改初始页把空统计仪表和展示卡片放在真实上传工作区之前；桌面端的主任务需要额外滚动，390px 移动端的装饰纸张还会把上传入口推到首屏外。这是以截图、DOM 顺序和真实视口坐标复核得到的布局问题，不是对教师行为的臆测。
4. 课堂导播在 390px 移动端把 7 张教学模式卡完整纵向展开，班级、诗篇、开课核验与启动按钮被推到模式预览之后。模式可选性本身没有问题，问题是小屏默认把“浏览全部选项”错误地置于“当前开课配置”之前。
5. AI 副驾在 390×844 的首次进入状态将模型、思考强度与温度配置排在主对话区之前，输入框坐标为 1056px，超过 844px 初始视口。隔离新页清除的仅是本地可恢复副驾草稿，不触碰认证或服务端会话；因此此结论针对真正首次进入的空会话，而不是被任务编排回归污染后的截图状态。

## 已实现的界面与交互改进

### 1. 教案工坊起始工作台

- 将未选模板时的空白区域替换为数据驱动的“备课起始页”，明确展示现有的 **选择模板 → 生成教案 → 审阅内容 → 按需导出** 四步路径。
- 起始页不声称“个性化推荐”，不自动替教师选模板，也不会进入生成流程。只有在模板列表已经有真实数据时，才出现“查看「当前第一份模板」”按钮；点击后仅执行原有 `selectTemplate`，展开真实的教学环节与适用关键词。
- 若模板仍在加载或筛选为空，按钮退化为状态提示，不制造虚假入口。
- 700px 以下视口将路径卡片改为单列，起始页按钮改为全宽；统计徽章切换为紧凑纵向结构、标签保持完整词组；360px 以下再退化为纵向页头，避免横向压缩或逐字断行。

### 2. 可控、可追溯的通知反馈

- Toast 容器避开 56px AppShell 顶栏，避免遮挡系统设置、通知中心和身份切换区域。
- 折叠态最多显示 2 条通知。错误和警告优先于普通成功/信息反馈；未展示的反馈仍保留在 Zustand 状态中，并提供“还有 N 条通知”可访问入口。
- 展开后可以阅读全部尚未过期的通知，再显式收起；没有删除、合并或把失败伪装为成功。按钮提供 `aria-expanded`、键盘可达焦点样式与窄屏宽度约束。

### 3. 智能批改的主任务前置

- 将“批改工作区”置于真实四步流程条之后；最近批次、空统计和展示卡片均移至工作区之后。初始页的阅读顺序因此变为 **确定班级/诗篇/题目 → 上传作业 → 识别 → 批改 → 审核**，不改变既有上传、识别、批改或审核业务状态机。
- 上传区增加稳定的 `#pr-grading-upload-zone` 语义锚点。未选择班级或题目时，原有文件输入仍保持禁用，并继续显示“先选择班级 / 诗篇与题目”的真实原因；本轮没有绕过归档前置条件，也没有自动打开本机文件选择器。
- 纸张堆叠仅承担装饰作用：桌面高度从最高 280px 收紧到 220px；900px 以下移到表单之后；480px 以下隐藏。最终 390px 截图可在同一首屏看到选择项、流程条、完整上传卡及保护提示。

### 4. 课堂导播的移动端模式收敛

- 大屏继续完整呈现 7 种教学模式；600px 以下初始只展示当前已选模式，并给出“展开其余 6 种教学模式”的明确按钮。教师可展开全量模式、选择后继续配置，并可再收起，未把任何模式删除或换成虚构快捷入口。
- 同时隐藏移动端无操作价值的自动轮播提示并收紧 Hero 间距，让班级、诗篇、题库核验和“开始课堂”配置卡紧随当前模式出现。题库未就绪时的“去命题工坊”与“系统不会用占位题开课”提示保持原样。
- 首次实现后 E2E 暴露通用模式卡 `display:flex` 覆盖窄屏隐藏规则；已改为父级限定的收起选择器。该修复来自浏览器失败证据，未把失败静默为通过。

### 5. AI 副驾移动端的“输入先于设置”

- 600px 以下的空会话将输入/语音辅助区移动到对话区顶部；四个真实快捷指令改为输入区之后的可选建议。教师先能直接描述问题，也能立即选择语音或常用要求，再决定是否展开并调整问答/任务编排、模型、思考强度与温度等高级配置。
- 已有会话不改变“消息流在上、输入区在下”的持续对话节奏；桌面三栏和全部模型控制保持原样。输入占位文案改为不依赖按钮相对位置的“输入教学需求，或选择常用要求快速开始”，避免界面说出与真实布局矛盾的话。
- 新增独立的首次进入回归：新浏览器页仅清除 `pr-copilot-state` 本地草稿、设置 390×844 视口并显式滚回页首；断言空会话的可编辑输入框在首屏、主对话区位于次级配置之前。初版门禁实际失败（配置栏 `top=-84`、对话区 `top=156`、输入框 `top=1056`）；修复后同一生产同源测试通过。

### 6. 创作迭代台的真实任务发布闭环

- 原页面可以查看任务和对内置样例执行规则化演示，却没有让教师把“创造任务”真正写入后端的入口；这会让界面看似覆盖“教师布置—学生创作”，实际只停在展示层。本轮在 Hero 区加入“布置创造任务”，展开后按需加载现有诗篇，要求教师选择目标诗篇、年级、任务类型与不少于 8 个字的任务要求，再调用既有认证 `createTask` API。
- 任务成功后立即进入“任务看板”，显示开放状态、目标诗篇、年级、类型、作用班级/未选择班级的真实范围和发布时间。未选择班级时界面只说任务已归属当前教师，**不**声称已经分发给学生；诗篇加载失败提供原地重试，加载中、空诗篇、未认证身份和提交中均会禁用发布或保留用户已填写内容，避免伪造成功。
- 旧有“AI 多维批改—应用反馈再创作”演示仍保留，但其“规则化演示”与“内置演示任务”边界未被移除。新增的发布流程证明的是认证下任务创建和回显，不证明真实学生提交、外部模型质量或教学成效。
- 首次回归时，任务看板的“继续布置任务”点击目标实测为 77×20px，未达到项目 24px 触控门槛。已调整为最小 32px 高的可访问按钮；该修复由失败证据触发，而非仅凭主观判断。
- 对 390×844 移动端新增独立发布起始态检查：点击主入口后，“目标诗篇”选择必须仍在首屏，诗篇和任务要求控件不能横向越界，确认发布按钮必须达到最小触控尺寸。该检查不二次提交任务，避免把回归数据伪装成额外教学记录；当前生产截图显示 Hero、真实范围提示、目标诗篇与年级选择均在首屏，证据为 `frontend/e2e-screenshots/regression/mobile-creation-task-composer-initial.png`。

### 7. 命题工坊的诗库局部降级可信边界

- 发现命题工坊在诗篇接口一次失败后会直接使用内置诗篇。原先只有短时 Toast；全局离线横幅要等更多失败信号才出现，Toast 消失后可能让教师误以为该诗篇来自当前真实诗库。这是通过阅读 `useWorkbenchStore.fetchPoems` 的失败分支以及浏览器故障注入复现得到的事实。
- 诗篇状态现在区分 `live`、全局 `demo-mode`、局部 `fallback` 与初始未知状态。局部 fallback 下，表单常驻显示“当前诗篇来自内置演示数据”、具体错误、不会写入教学记录的边界以及“重试真实诗库”入口；只有重新取得真实诗库才撤销该状态。

### 8. AI 副驾物料库的数据来源与隐私边界

- 发现 AI 副驾的“学生”标签在非 DEMO 状态也固定呈现本地姓名样例，而“诗词”标签在真实诗库请求失败时静默换为内置演示诗篇。两者都会进入 `@[类型:ID:标题]` 上下文引用，因而不仅是视觉问题，还可能让后续 AI 建议基于被误认为真实的学生或诗篇。此结论来自对 `QuickActions` 数据分支的代码审查及浏览器 503 故障注入，不是对产品行为的推测。
- 正式模式现在只读取 `/api/students` 返回的匿名学生标识和 `/api/workbench/poems` 返回的真实诗库；演示模式中的学生改为“演示学生 01”这类不可误认的标识。单接口错误不会再切入演示物料：当前标签会常驻展示真实来源不可用、说明未替换数据，并给出精确的重试入口。
- 知识点标签继续提供内置教学参考，但在当前操作位明确说明其用途是组织提示词，而非联网检索结果或学生学习记录。错误提示改为教师可理解的业务文本，不把原始 `API 503` 等实现细节作为主要界面文案。
- 为避免把演示输入送入貌似真实的命题链路，fallback 下教师仍可预览选择、年级和权重等界面，但“启动六阶命题”改为禁用的“等待真实诗库恢复”。若已经成功加载真实诗库而刷新失败，则继续使用已加载的真实诗篇并单独披露“未能刷新”，不以演示数据覆盖原数据。
- 全局 DEMO 模式退出时，命题表单会对曾加载的 `demo-mode` 诗篇重新拉取真实诗库；局部 fallback 则只允许教师主动重试，避免短暂网络抖动造成无限请求循环。

### 9. 课堂开课入口与创新模式的可信可用性

- 发现课堂开课页在 `/api/workbench/poems` 失败后仍保留 `POEM_IMAGES` 的本地图谱诗目。注释已经说明它们并非后端题库主键，但界面仍可展示为“诗篇”选择项，易造成教材来源可用的错误印象；这是阅读 `ClassroomPage` 初始状态与失败分支后，再以浏览器 503 注入复现的事实。
- 正式状态现在仅展示接口返回的规范诗篇。首次真实诗库故障会清空选项、清除选择值、禁用诗篇选择与“开始课堂”，并常驻说明“未显示本地样例”；已成功取得过的真实列表才允许保留，且必须标为 `stale-live`，可由教师手动重试刷新。全局演示状态也单独标明“离线演示数据”，不把它伪装为真实教学材料。
- 进一步审查发现前端定义和展示了 7 个课堂模式，而课堂启动、开课核验、运行中切换、课堂会话创建和命题发布的后端校验此前只允许 4 个基础模式；选择“诗词大转盘”“诗词接龙”或“意境拼图”可能返回 400。这是由 `frontend/src/lib/types.ts` 与后端 Zod 枚举的直接对照得到的源码事实，不是推测。
- 后端现以单一 `LESSON_MODES` 常量统一五处输入校验，并补齐课后报告中的创新模式名称；命题工坊发布模式的类型和通知标签也同步为完整 7 种模式。数据库以文本存储模式值，没有新增迁移或对既有课堂记录的破坏性改写。
- 运行中的“诗词接龙”以前在活动级诗库失败时会用本地样例和硬编码首句启动。现在它与开课入口遵守相同状态机：无真实来源时清空、禁用“启动接龙”；已有真实来源刷新失败只披露为旧数据；真实接口恢复后才重新开放选项。这样离线演示、陈旧真实数据和实时真实数据不再互相冒充。
- 本轮继续审查课堂运行态，发现“共舞舞台”此前会接收所有 `dance:*` 广播而未核对 `sessionId`，且切换 `lessonId` 时旧事件流、流式文案和输入草稿可能短暂残留。这是前后端统一事件信封已明确携带 `sessionId`、而前端订阅未过滤的源码对照事实。现改为只接受 `sessionId === lessonId` 的事件；切课先清空旧态；历史事件获取失败明确显示“事件流暂不可用”并给出重试，不再误显示为“共舞尚未开始”。
- 课堂内嵌的逐句讲解 / 正音专练和共舞的布置 / 引导 / 反馈此前只有视觉选中状态，缺少 `aria-controls`、唯一 roving `tabIndex`、Arrow/Home/End 与动态 `tabpanel` 关联。现补齐这些实际交互契约；共舞尚未启动时，切换指令仍会同步可访问名称和建议区，但输入与发送保持禁用，防止教师误以为指令已经进入课堂。

### 10. AI 副驾干预建议的语义与采纳回执

- 发现课堂副驾的“干预建议”此前没有对应前端调用的后端接口：点击后实际请求的是追问生成，却在界面、业务事件和采纳统计中写作“干预建议”；同时“采纳”在持久化请求失败时会先展示成功。这两个结论来自 `AIAssistant` 的分支和回调代码，以及生产 E2E 的首次 400 失败证据，不是推测。
- 已将后端已有的 `detectIntervention` 聚合服务接到认证的 `POST /api/classroom/:lessonId/ai/intervention`，只分析本节课堂已经提交的作答，以正确率低于 40% 为当前支持阈值，返回当前需重点支持范围、正确率和全班建议。界面会明确标注“规则化分析，不等同于长期学情结论”，避免把一次课堂快照误表述为完整画像。
- 干预建议是聚合结果，不伪装成流式模型生成；采纳按钮在服务器确认成功前显示“保存采纳中…”，失败则显示“采纳状态未保存”，不会让 UI 与报告统计分叉。其接口采用 `{}` JSON 正文，满足 Fastify 对已声明 `application/json` 的非空正文约束。

### 11. 思考宫殿的受限环境性能与可访问性

- 构建证据显示 `three-vendor` 是按需加载的重型分包（gzip 约 225KB），入口页不预载它；但此前思考宫殿切到 AI 审计后会直接渲染懒加载 3D 组件，即使浏览器明确请求“减少动态效果”、设备是窄屏、开启节省流量、报告低内存或根本不支持 WebGL。组件内部的 WebGL 失败兜底发生在资源已经请求之后，不能称为完整性能兜底。
- 现在把判断前移到懒加载边界：受限环境先展示“轻量二维审计”，按顺序提供每个节点的类型、原内容、选中状态与键盘可达按钮；它不是骨架或摘要替身。无 WebGL 时保持二维视图；其余受限环境由教师明确点击“开启沉浸 3D”后才加载 3D 代码，仍尊重组件已有的减少动态行为。
- 这项策略不使用未经验证的设备评分或伪造网络状态：只读取浏览器已经公开的 `prefers-reduced-motion`、视口、`saveData`、`deviceMemory` 与 WebGL 可用性；缺失的可选提示不会被当作低性能结论。二维视图只改变呈现与资源加载时机，不改写思考链数据、播放状态或节点详情的真相源。

### 12. 诗脉星图的受限环境目录优先

- 星图原本已具备真实数据目录，但在减少动态和窄屏条件下仍会默认请求并渲染沉浸 3D；这会让遵循辅助技术偏好的教师被迫下载重型 WebGL 分包，也不利于课堂投屏或低性能终端的首次稳定进入。
- 2026-08-10 的后续重写保留可搜索、可键盘点选的真实星体目录，并将教师主动开启的沉浸视图改为项目原生的 StarMapDome 语义诗篇画廊；两种视图都使用同一份节点、筛选、关系透镜和详情数据，不以静态图片或演示数据替代教学内容。
- 当前开启 StarMapDome 前后均不请求 Three.js、WebGL、Canvas 或 `three-vendor`；`docs/audit/production-e2e-latest.json` 的受控触控、选择、失败图片和资源计时契约已记录为 `checked: true`。这只证明相应前端路径，不证明关系内容真实性、教学效果、所有浏览器长期内存表现或比赛结果。

### 13. 长期记忆治理的破坏性操作确认

- 发现“清空本班学生记忆”此前采用浏览器原生 `confirm`，不同浏览器、投屏设备或自动化环境的呈现和键盘路径不可控；而且只要选中班级，即使当前页面在“教师偏好”范围也会显示该学生数据操作。这是源代码与原有浏览器回归直接确认的事实。
- 现在仅在“学生学情摘要”且已选班级的真实作用域中显示清空入口。首次点击展开页面内警告，清楚说明不可撤销边界和不会影响的教师偏好；教师可以取消，或经第二个明确按钮才发出删除请求。成功后才关闭确认区并刷新列表，失败则保持可见以便重试或取消。保存新摘要后保留当前数据范围，不再把学生摘要写入后突兀切回教师偏好。
- 同时为范围切换期间的列表读取增加单调请求序号：旧请求即使在新请求之后返回，也不能覆盖当前范围的项目和加载状态。该保护只解决前端状态竞争，不把后端删除结果、权限或真实数据来源伪装成已验证的结论。
- 新确认区复用现有面板的键盘焦点样式和最小 30px 操作目标，不嵌套第二个全局模态层，因此不会和“系统设置”既有的 ESC/焦点陷阱相互干扰。确认区打开后的下一帧会滚动到设置面板的可视中部，避免位于长设置页底部时只露出警告文字却把取消/确认按钮裁切在视口外。

### 16. 进化之眼的空证据闭环与无效 3D 截断

- 视觉复核发现：在没有持久化版本谱系时，旧页面仍会渲染一个占据大块空间的 3D 容器，只显示“暂无版本谱系数据”；切到零模式页时也只有单行占位。这既掩盖“尚无可审计证据”的事实，也会让教师误以为页面或单次演示应当生成 AI 版本。该问题由桌面截图、`Genealogy3D` 空数据渲染路径、`PatternPanel` 空分支以及进化引擎仅在教师纠正/智能体错误/验证否决等条件下持久化信号的源码共同证实。
- 现在空谱系不实例化 `Genealogy3D`，并明确说明页面、单次任务和演示模式不会虚构候选、质量分或 A/B 结果；教师可刷新三个持久化证据源、打开 AI 运行证据，或查看真实采集条件。已有模式而未形成节点时优先显示已有模式，而非空 3D 舞台。
- 零模式状态不再展示无意义的排序筛选或留白，而是列出“教师纠正被确认、智能体错误被记录、验证结果明确否决”三类来源，并提供同样的刷新和运行证据入口；仅筛选导致的零结果可一键清除筛选恢复。这样没有证据时不补数，有证据时不隐藏，也不把来源不明的演示内容当成进化结果。
- 密码鉴权生产 E2E 将三个真实 evolution API 固定为合法空集合，断言空谱系的禁止伪造说明、无 `three-vendor`/`Genealogy3D` 资源请求、两个空态的三源刷新、模式采集边界与进入 AI 运行证据页；桌面证据为 `frontend/e2e-screenshots/regression/desktop-evolution-eye-empty-evidence.png`。这证明当前生产构建在该受控空数据路径上通过，不替代真实学校模型调用、长期运行和人工证据审核。

### 17. 组合框鼠标展开与批改结果表的单次触发、键盘语义

- 源码审查发现共享 `Combobox` 的输入框 `focus` 会打开选项，而同一次鼠标点击又冒泡到父级触发器并再次切换开闭状态；在 React 刷新时序下，菜单可能刚打开便被关闭，班级、题目等鼠标选择不稳定。此结论由事件处理路径与失败的生产浏览器复现共同证实，不是由截图猜测。
- 现在输入框点击只保证打开列表；箭头和输入框外的触发区域仍可正常切换。该修复位于共享组件，保留键盘 Arrow/Enter/Escape、筛选、多选标签和失焦关闭行为，同时避免为某一个页面添加特例。
- 批改表此前让 `AnimatedList` 外包装和内部结果行都接收选择回调，同一次指针点击可能经过两个状态写入；包装层与表格单元的 ARIA 层级也不完整。现在结果区使用 `table → rowgroup → row → cell`，动画包装显式为 `presentation`，只有结果行响应点击/Enter，且使用 `aria-expanded` 与 `aria-controls` 关联详情行；详情单元以 `aria-colspan="5"` 声明跨列。
- 密码模式生产 E2E 用明确标识的受控 API 响应走真实教师界面路径“选择班级/题目 → 上传 → 识别 → 批改”，验证鼠标展开不自闭合、结果行单次触发、详情可由 Enter 折叠并再次展开，以及完整表格语义。该受控样本只证明前端交互/ARIA 契约，**不**证明真实学生、OCR 或模型评分效果。截图证据为 `frontend/e2e-screenshots/regression/desktop-grading-result-table-keyboard.png`。

### 18. 诗境图片卡片与诗篇模块的独立操作、键盘和焦点闭环

- 源码审查发现，诗境图片卡片原先将下载链接嵌套在带 `role="button"` 的卡片中；这会让两个独立操作在键盘语义上相互竞争，也会形成不合法的交互元素嵌套。现改为列表项内的原生“查看大图”按钮与独立下载链接：预览和下载各自有明确名称，预览按钮内不再包含链接。
- 诗篇重构侧栏此前把标题、说明、页脚与实际模块按钮混在同一个 tablist 中，模块按钮缺少稳定的 Tab—面板关联和标准键盘行为。现将 tablist 收紧到实际导航，使用 roving `tabIndex`、`aria-selected`、`aria-controls` 与 `tabpanel`/`aria-labelledby`，支持 Arrow、Home、End 在路线、顾问、生图、朗诵之间切换。
- 同一轮审查还发现顶层“诗篇重构 / AI 推理审计”与“学生成长 / AI 进化”只具备视觉选中态；在其 AI 数据加载或出错时，早退渲染会卸载切换器，用户无法用键盘或鼠标返回另一视图。现在两组顶层 tablist 都有命名、唯一面板关联和 roving `tabIndex`，支持 Arrow/Home/End；加载骨架和错误回退被放入仍然存在的 tabpanel 内，保证切换入口持续可达。
- 思考路线原先给原生 `<button>` 覆盖 `role="listitem"`，使屏幕阅读器失去按钮语义；思考链/节点又以 `article role="button"` 手工复刻键盘行为。现在路线为 `ol → li → button`，链和节点卡片改用原生 button，保留 `aria-pressed` 和视觉样式，交互不再依赖手写 Enter/Space 分支。
- 大图层现在在打开后将焦点放到关闭按钮，Tab/Shift+Tab 不会逃逸，Escape 和遮罩可关闭，并将焦点归还到触发预览的同一张图片按钮；关闭按钮阻止事件冒泡，避免一次点击重复触发两次关闭。
- 密码模式生产 E2E 以明确标注的 SVG 受控图片响应验证这组 DOM 与焦点契约，截图证据为 `frontend/e2e-screenshots/regression/desktop-thinking-palace-image-card-accessibility.png`。受控图片只证明前端结构和交互，**不**作为生图模型质量、供应商可用性或教学成效证据；真实供应商拒绝时仍由产品既有本地插画降级路径处理并持续披露。

### 20. 诊断异步隔离与告警操作层级

- 诊断页曾以通用 `unwrap` 只移除响应的 `status` 字段，但学生个性化处方的服务契约是 `{ status, output }`。这会令前端把外层对象误当 `PrescriptionOutput`，随后 `SuggestionPanel` 读取 `weaknesses.slice` 时触发路由级错误边界。现改为专用 `unwrapPrescriptionOutput`：必须存在对象型 `output`，且画像、优势、弱项、建议、资源、活动与目标七个数组字段完整；畸形响应转为可见、可重试的加载错误，不能再以空白错误页作为兜底。
- 学生切换已经清空上一位学生的画像、漏洞、规则路径、AI 路径、处方和流式可见文本，普通异步读取在提交前再次核对学生 ID。对 AbortController 无法绝对阻止的网络缓冲末帧，学习路径、处方和 AI 建议再增加单调会话 token：取消、清空、重试和切换都会使旧 token 失效，任何迟到分片、完成或错误回调均不能写回新会话。该实现已通过 TypeScript 与全量生产 E2E 回归；但当前 E2E 尚未用受控 SSE 特意制造取消后的迟到分片，因此不能把一般页面通过夸大成对此时序组合的穷尽证明，后续需补专用夹具。
- 告警此前存在可聚焦、可点击的外层 `article` 与内嵌跳转按钮两个等价操作点，并且 JSX 的等级/详情/底栏类名与 CSS 选择器失配。现在告警卡片只作为 `listitem`，唯一 CTA 按钮承接导航，名称包含“动作：告警标题”，具备独立 hover、active、focus-visible 与至少 28px 高的触控目标；徽章、详情和底栏改为实际样式类。生产同源 E2E 使用明显标注的受控告警验证唯一焦点入口、可访问名称、Enter 导航和样式结构。该告警只证明 UI 契约，**不**是学生风险、教学质量或模型效果证据。
- 学生列表曾同时让外层 `listbox` 和每个内嵌原生按钮进入键盘焦点序列，并用 `role="option"` 覆盖按钮语义；这会造成额外 Tab 停靠点和控制类型冲突。现在容器只标为命名 `group`，学生项保持原生按钮，以 `aria-pressed` 与唯一 roving `tabIndex=0` 表达当前选择。方向键、Home、End 请求的焦点会等 React 提交选中态后再恢复，避免异步状态写入把焦点留在旧项；鼠标点击与初始自动选中不会反向抢焦点。生产同源 E2E 在临时 SQLite 学生夹具中实际验证 Home → ArrowDown → End → Home 的选中态、唯一 Tab 入口和 DOM 焦点三者同步。该夹具只证明界面选择机械性，不作为学生或学习成效证据。

### 21. 批改进度像素过渡的多输入一致性

- `PixelTransition` 原先把桌面 `focus` 当作悬停替身，并且仅触摸设备可通过 click 触发。它虽然被放入 Tab 序列，却没有按钮角色、可读名称、状态披露或 Enter/Space 行为；键盘用户无法明确知道该焦点能够做什么，且焦点本身会意外改变展示内容。
- 组件现在保持鼠标 hover 的视觉渐进增强，但所有平台都共享同一显式切换路径：原生可聚焦控制器暴露 `role="button"`、调用方提供的可访问名称和 `aria-pressed`；click、Space、Enter 都通过同一个状态机切换。焦点不会再仅因进入控件而自动改变内容。
- 生产同源 E2E 以隔离受控的“上传—识别—批改”流程产生真实前端状态，再验证“切换批改进度概览”的初始状态、Space 打开、Enter 关闭和每步焦点保持。该夹具仅证明前端输入与状态契约，不作为学生、OCR 或模型批改成效证据。

### 22. 命题富内容与详情焦点的完整闭环

- 命题题干由 Markdown 渲染，可合法包含真实来源链接、图片及代码复制控件。此前题干外层被赋予 `role="button"` 和键盘点击行为，会把这些真实交互元素嵌入伪按钮，既违反交互语义，也会让教师误以为整段文字是唯一入口。
- 题干现在保持为普通富内容容器，题卡操作栏提供唯一、明确的原生“查看完整详情”按钮。它的可访问名称与当前卡头题号同步，并披露会打开对话框；题干中的链接、图片与复制操作继续保有各自独立的键盘路径。
- 审查同时发现：题卡详情以条件渲染关闭时会直接卸载共享 `Modal`，使此前仅依赖 `open=false` effect 的焦点恢复失效。共享弹窗已增加卸载兜底：无论完成离场还是父组件条件卸载，均尝试以 `preventScroll` 恢复到已连接的原触发控件；路由卸载后失效的节点不会被强行聚焦。这是通用可达性修复，而非只覆盖题卡。
- 生产同源 E2E 将该链路设为独立硬门槛：仅注入一条显式标识、带来源链接的受控题卡，验证题干无伪按钮语义、链接保留、详情入口唯一且题号同步、Enter 打开、Escape 关闭以及焦点归还。该夹具只证明前端富内容与无障碍契约，**不**作为学生、教学质量或模型效果证据。

### 23. 进化模式到可核验谱系版本的闭环

- 源码审查发现进化模式卡原先既充当 `article role="button"`，又置于 `role="list"` 中，形成没有 `listitem` 子项的伪列表；更关键的是，点击只切换到“族谱”标签，没有选中任何具体版本，注释中所谓“高亮对应节点”与实际行为不一致。结论来自组件事件路径、数据联接路径和受控浏览器复现，不是由页面外观推断。
- 现在模式区是语义明确的 `list → listitem`。聚合键改为“模式文本 + Agent”，同名模式不能借用其他 Agent 的次数、提升值或谱系边；每条模式仅在精确匹配的持久化边能指向仍存在的节点时，才显示单一原生“查看关联版本”按钮。多条可用边按持久化时间倒序，定位最新仍可用目标；关联芯片展示可区分的真实版本名而非相同 ID 前缀。没有边的模式保留信息但不制造跳转入口，目标失效边则明确显示“关联节点已失效”及可追溯节点 ID；一次交互间发生数据变化时，操作处理器仍会失败关闭并提示刷新证据。
- 键盘 Enter 激活后，界面选中目标节点、切换到族谱面板，并把焦点转交给新 `tabpanel`，避免原按钮随模式面板卸载后焦点落入 `body`。截图复核为 `frontend/e2e-screenshots/regression/desktop-evolution-pattern-linked-navigation.png`。
- 生产同源 E2E 以四个明确标识的受控模式和两代同源节点验证：列表没有整卡伪按钮；跨 Agent 同名模式不能借边；可用关系的版本芯片可区分；无边与目标已失效边均无跳转控件，后者明确披露失效状态；有边且节点存在的模式恰有一个原生动作；Enter 最终选中最新版本并完成标签、详情和 DOM 焦点交接。390×844 下再验证无横向溢出、唯一入口未裁切且实际高度不少于 32px。夹具仅证明前端语义、已保存证据联接和交互可靠性，**不**证明真实 AI 长期进化、教学效果或模型质量。

### 24. 报告历史的原生表格、焦点与窄屏决策链

- 源码审查发现通用 `Table` 曾允许通过 `onRowClick` 把原生 `tr` 伪装成带 `role="button"` 与 `tabIndex=0` 的整行操作；报告历史又在行内提供查看、删除等原生按钮。这既让一个列表项出现重复操作入口，也让键盘用户在“查看”后因按钮变为禁用的“当前”状态而丢失焦点。结论来自共享组件调用关系、渲染属性和隔离浏览器复现，不是由视觉猜测得出。
- 共享表格已恢复原生行语义；报告历史仅由按报告标题区分的原生“查看 / 删除 / 确认删除 / 取消删除”操作触发。查看完成或失败报告后，焦点明确转交到刚载入的报告标题；生成中报告仍不提供查看入口，避免把未完成内容冒充为可读结果。

- 生产同源 E2E 注入明确标识的已完成、失败和生成中报告，验证原生行没有按钮角色/Tab 停靠/隐式详情读取；完成和失败状态均有唯一具名操作、生成中状态失败关闭；中性标题单元格不请求详情；Enter 只请求声明的报告并把焦点交给标题；390×844 下断言标题可见、表格和页面均无横向溢出、操作未裁切。夹具只证明前端表格、焦点和响应式契约，**不**证明报告内容、教学质量或模型效果。

### 25. 答题图片堆的原生操作、拖拽抑制与大图焦点闭环

- 源码审查发现答题图片堆把可点击卡片写成 `div role="button"`，却没有键盘激活处理；仅顶部卡片可 Tab 到达。大图预览没有初始焦点、正反向 Tab 边界或关闭回焦。这个结论来自实际组件事件/ARIA 属性与浏览器受控流程复现，不是从截图猜测得出。
- 卡片已改为无嵌套交互的原生 `button type="button"`，所有可见叠卡均可由 Tab 到达；画廊获焦和预览打开都会暂停自动播放。拖拽距离超过 8px 后的浏览器补发 click 会在 250ms 小窗口内被吞掉，避免“拖动翻牌 → 紧接着误开预览”的组合性故障；正常鼠标、触摸和 Enter/Space 的按钮激活仍保留。

### 26. 星图沉浸导航的关闭态语义与遮罩回焦

- 源码审查发现星图页的 `ImmersiveShell` 始终渲染抽屉 `<aside role="dialog" aria-modal="true">`，仅用 `transform: translateX(-100%)` 移出屏幕。视觉关闭并不等于语义关闭：屏幕阅读器仍会遇到模态对话框，隐藏链接也可能继续进入 Tab 序列；遮罩点击关闭时原先没有统一的焦点归位。结论来自 DOM 属性、CSS 与真实路由浏览器复现。
- 关闭态现不再赋予 `dialog` 或 `aria-modal`，改用 `aria-hidden="true"` 和 `visibility:hidden` 双门退出可访问树、键盘焦点与指针命中；打开才恢复对话框语义。遮罩、Escape 和显式关闭按钮共用关闭路径，动画帧后回到“打开导航菜单”触发器；抽屉开启后的首个焦点仍是明确的关闭按钮，首尾控件构成 Tab/Shift+Tab 边界。
- 生产同源 E2E 在实际 `/starmap` 路由验证关闭态、Enter 打开、初始焦点、正反向 Tab、遮罩关闭后语义移除与焦点归还；390×844 额外验证抽屉不超过视口 80%、关闭控件至少 40px，且无页面横向溢出。夹具只证明前端导航与几何，不代表星图数据、教学质量或模型效果。

### 27. 空通知对话框的焦点兜底与小屏视口锚定

- 源码审查发现通知列表为空时，面板内没有可 Tab 到达的控件；既有焦点陷阱会尝试聚焦面板本身，但面板缺少 `tabIndex=-1`，导致 `aria-modal` 可能仍由外部铃铛持有焦点。窄屏样式还以右侧工具组内的铃铛为定位参照，390px 实测面板左缘为 -21.73px，属于真实的可复现裁切，而非截图推测。

### 35. 诗境生图资源失败的可恢复状态

- 静态审查发现生图接口返回图片 URL 后，卡片只处理了 `onLoad`：CDN 中断、临时签名 URL 失效、离线或资源被清理时，`onError` 未终止骨架屏，用户会持续看到“正在加载”的假象；预览和下载仍可指向同一失效 URL。大图层亦没有独立失败反馈。这是“接口成功但交付资源失败”的真实边界，而非单纯的视觉缺陷。
- 图片卡片现区分 loading / loaded / failed：失败时以具名状态替换骨架，禁用大图入口、移除失效下载入口，并提供“重新加载”操作；HTTP(S) 重试仅附加无语义缓存键，`data:`/`blob:` 地址保持原样。大图层采用同样的失败状态与重载按钮，仍可关闭或切换相邻图片，避免把暂时不可用资源包装成可交付结果。
- 生产同源 E2E 的受控图片接口先返回可显示资源，再返回被浏览器实际中止的 HTTP(S) 图片请求；它验证失败态出现、预览禁用、下载入口移除以及重载发出带缓存键的新请求，并在 `prefers-reduced-motion: reduce` 下读取成功/失败卡的计算透明度，要求两者均为可见终态。该夹具只证明前端资源恢复、焦点、可见性与控件诚实性，不证明生图模型质量、供应商可用性或教学效果。截图：`frontend/e2e-screenshots/regression/desktop-thinking-palace-image-card-accessibility.png`、`frontend/e2e-screenshots/regression/desktop-thinking-palace-image-load-failure.png`。

### 36. 共享 Markdown 图片的失败诚实性

- 共享 `Markdown` 组件被 AI 副驾、报告、命题与文化语境等多条真实业务路径复用，但原实现只在 `onLoad` 后清除模糊滤镜；HTTP 资源中止、离线、CDN 故障或短期签名过期时，组件会停留在“模糊加载中”，没有文字说明、替代文字上下文或恢复动作。这一结论来自组件实现和生产浏览器中的中止资源请求，而非假定外部服务不稳定。
- 组件现维护 loading / loaded / failed 三态。失败时把破图元素替换为 `figure` 内独立的 `figcaption[role=status][aria-live=polite]`：明确提示“图片加载失败”、保留 Markdown `alt` 的可读上下文，并让原生“重新加载”按钮保持在 live region 之外；对 HTTP(S) URL 才附加无语义缓存键，`data:`/`blob:` 地址不被改写。此修复不宣称图片本身已经生成成功，也不把缺图包装成模型输出。
- 密码认证生产 E2E 从真实 AI 副驾输入触发受控 SSE 回复，再在浏览器资源层实际中止该 HTTP(S) 图片请求；断言错误状态、替代文字、破图元素移除和带 `_prMarkdownImageRetry=1` 的新请求均成立。截图：`frontend/e2e-screenshots/regression/desktop-ai-copilot-markdown-image-load-failure.png`。该夹具仅证明共享前端资源失败恢复，不证明 AI 回复质量、图片模型质量、供应商可用性或教学效果。

### 38. 评分工作流图片的非空失败终态

- 深入审查评分页的本地预览、识别结果、详情、批改前后对比和答题图片堆后发现，它们各自直接渲染 `<img>`。一旦对象 URL 被提前回收、受保护媒体签名过期、网络离线、CDN 中断或图片损坏，浏览器会留下一块空白或默认破图；尤其答题图片堆的大图层会把“点击已成功”误呈现为空预览。此结论来自实际调用点、资源 URL 传播路径和浏览器中止请求复现，而非根据截图推测。
- 现在这些评分路径统一通过 `GradingMediaImage` 渲染。失败状态与具体 URL 绑定，新 URL 会重新获得加载机会；失败时原图替换为具名、礼貌播报的“图片暂不可用”终态，保留原替代文本作为无障碍名称，不伪造图片已加载。上传缩略图仍保留删除入口、文件名和上传进度；答题图片堆仍可打开其具名大图，以让教师明确区分“媒体不可用”与“交互无响应”。
- 密码认证生产 E2E 在真实班级/题目选择、上传、识别、批改链路中让一张受控学生图片保持可解码、实际中止另一张媒体请求；验证失败卡片及其大图均为 `role=status`、`aria-live=polite`、不含破图 `<img>`，并继续验证 Escape 返回源卡片和 390×844 无横向溢出。截图：`frontend/e2e-screenshots/regression/desktop-grading-stack-gallery-accessibility.png`、`frontend/e2e-screenshots/regression/mobile-grading-stack-gallery-accessibility.png`。该夹具只证明前端媒体失败恢复、语义、焦点和几何，不代表学生作品、OCR、批改质量或模型可用性。

### 39. AI 副驾图片附件的预览失败关闭

- 图片附件会先在浏览器压缩成 data URL；该数据原先同时承担缩略图与多模态请求内容。深度审查发现，压缩成功并不保证后续 `<img>` 一定能解码：浏览器内存压力、解码器异常或损坏的压缩产物都可能让缩略图进入 `error`。若仍把同一内容静默交给模型，教师看到的界面状态会与实际发送内容分叉。该风险来自 `useAttachments` 的数据流和缩略图渲染使用点，不能仅用“压缩 Promise 已成功”推断为可交付。
- 现将已就绪图片的真实 `onError` 收敛为一次性失败关闭：缩略图替换为具名、礼貌播报的警示状态，明确说明“附件不会发送给模型”，保留文件名及原生“移除并重选”入口；`buildContent` 只选择 `ready` 附件，故失败图片不会形成 `image_url` 片段。该策略不阻断教师继续发送纯文字，避免单个媒体故障扩大为整段教学咨询不可用。
- 同时约束移动端几何：错误文案可在卡片内换行，不得撑破输入区；移除入口为至少 24×24px。密码认证生产 E2E 使用项目内真实 PNG 走文件选择、`createImageBitmap` 与 canvas 压缩链路，随后对已挂载的真实图片节点派发受控 `error`；在 1440×900 验证状态语义、缩略图移除、失败附件从下一次请求负载排除及纯文字可发送，在 390×844 验证无页面横向溢出和 24px 移除目标。截图：`frontend/e2e-screenshots/regression/desktop-ai-copilot-attachment-preview-failure.png`、`frontend/e2e-screenshots/regression/mobile-ai-copilot-attachment-preview-failure.png`。夹具证明前端恢复、请求排除和响应式几何，不证明图片内容、学生数据或模型效果。

### 40. 跟读录音的异步会话收尾与取消边界

- `getUserMedia`、`MediaRecorder.stop()`、最终 `dataavailable` 与 `onstop` 不在同一同步调用栈。静态审查发现，若把点击停止、权限提示期间的第二次点击、组件卸载、父级进入禁用态和迟到的授权结果混作同一条路径，就可能出现两类相反错误：正常停止在最终音频块到达前结束，或用户已取消/离开朗诵模块后仍悄悄启动麦克风并把无归属音频交给 ASR。该结论来自 `VoiceInput` 的异步资源所有权与浏览器 API 回调顺序，不是从界面外观推断。
- 录音现以显式会话持有 recorder、stream、chunks、一次性交付标志和幂等轨道回收函数。正常停止保留 chunk，等待 `onstop` 后才生成 Blob 且至多回调一次；权限请求阶段显示“再次点击取消”，取消、禁用、卸载和新的启动请求会推进请求序号、取消交付、停止 recorder/轨道并清理计时器。迟到的授权结果比较请求序号、挂载状态与禁用状态后立即释放轨道，绝不启动 recorder；按住模式同时覆盖释放、`pointercancel`、失焦与 Space/Enter 等价操作；空 Blob 或 recorder 异常均显示可重试的明确状态，不能伪装为已识别。
- 密码认证生产 E2E 使用隔离、可观测的浏览器媒体设备和受控 ASR 响应，仍通过真实诗篇模块、录音按钮和 `/api/ai/asr` 路径验证：正常停止等待最终 chunk 并仅发出一次 multipart ASR 请求；权限阶段再次点击会释放迟到流而不启动 recorder/不提交 ASR；模块卸载后的迟到授权只释放轨道；录制中卸载会停止设备并取消最终交付。截图：`frontend/e2e-screenshots/regression/desktop-thinking-palace-voice-input-lifecycle.png`。夹具只证明前端录音生命周期与请求边界，**不**证明真实麦克风采集、学生发音、ASR 准确率、供应商可用性或教学效果。

### 42. 复用快捷语音的可撤销授权与卸载边界

- 静态审查发现，`QuickVoiceAssist` 不是朗诵模块的局部控件：AI 副驾、课堂、备课、诊断、批改和思考宫殿等主路径均复用它。旧实现会在 `getUserMedia` 等待期禁用按钮，既不提供取消意图，也没有请求代次；父级随后禁用或用户离开页面时，迟到的授权存在启动无归属录音的风险。该结论来自共享组件的真实调用面、异步状态转换与媒体资源所有权，而不是视觉截图推断。
- 组件现以显式会话持有 recorder、stream、chunk、交付标志及幂等轨道回收；等待授权时按钮保持可达并明确显示“正在请求麦克风权限，再次点击取消”，第二次点击、父级禁用和卸载都会推进请求代次、取消交付、停止现有设备并清理计时器。正常停止仍等待最终 `dataavailable` / `onstop` 后发起一次 ASR；取消或卸载后的迟到 stream 只会关闭轨道，识别结果只回填可编辑输入，绝不自动发送。

### 45. 减少动态偏好的全路由硬门禁

- 原有 CSS 同时存在两条相互矛盾的规则：`tokens.css` 将减少动态环境下的时长全局压缩为 0.01ms，而 `micro-interactions-v5.css` 以更高优先级的 `!important` 把 v5 页面入场/错落动画改为 200ms 淡入。真实浏览器在密码认证生产 E2E 中复现了这条覆盖链：桌面和移动端的仪表盘、星图、诊断、命题、课堂、批改、文化、报告、隐私等页面均仍有超过 20ms 的 CSS 动效，部分稳定页面还能观察到长时 DOM Web Animation。该结论来自计算样式和 Web Animations API，不以源文件中“有媒体查询”作推断。
- 现删除该逆向覆盖的 200ms keyframes，并在同一选择器上显式 `animation:none!important`、清除错落延迟、释放 `will-change`。这只关闭 v5 装饰性入场动效；内容默认以最终可用状态出现，功能性焦点、加载/失败状态和专门的 Three/WebGL 轻量视图降级逻辑保持各自语义。
- 严格 E2E 现在在全部 16 条路由、1440×900 和 390×844 共 32 个界面—视口组合中执行 `reducedMotionCompliance`：媒体查询必须实际生效；可见 CSS animation/transition 不得超过 20ms；页面稳定后不得遗留长时 DOM Web Animation；同时将 checkbox、combobox、menuitem、option、radio、slider、switch、tab 等自定义 ARIA 角色纳入运行时可访问名称检查。最终新构建结果为 32 组合、0 警告、0 失败、0 条超时 CSS 动效、0 个稳定页长时 DOM 动画、0 个无名称交互控件。Three/WebGL 等 DOM 外路径继续由既有轻量视图专项回归验证，因此没有把该 DOM 门禁夸大为全部渲染技术的保证。

### 47. 生产同源 E2E 的 Node ABI 失败关闭

- 在本机重新执行时，父命令表面上经由 Node 20 调用 Corepack，但机器 PATH 中的系统 Node 24 仍可被 pnpm 脚本解析为实际运行时。隔离 E2E 的后端子进程按设计使用 `process.execPath`，因此继承了这个错误的 Node 24；而 `better-sqlite3` 已按锁定的 Node 20 ABI 编译，服务在启动时以 `NODE_MODULE_VERSION 115` 与 `137` 不匹配退出。这个结论来自真实 Fastify 子进程堆栈和 ABI 错误，不是根据 package.json 推测。
- `run-e2e-isolated.mjs` 现在在创建临时目录、端口或服务前强制要求 `Node >=20.19 <21`。错误运行时会以具名错误立即失败，并直接说明其与 SQLite 原生模块的 ABI 风险；正常路径继续使用 `process.execPath`，因此后端和浏览器回归进程保持同一 Node 实例。该门禁不把 Node 24 当作可替代的“构建成功”环境。
- 负向验证中，系统 Node 24.15.0 以该具名错误在后端启动前退出；正向验证在官方校验的 Node 20.20.2、Corepack pnpm 10.34.5 且 PATH 首位固定为同一 Node 目录的环境中执行。密码认证生产同源 E2E 完成 32 个界面—视口组合，0 警告、0 失败，临时端口已释放。它证明运行时一致性和前端回归可启动，不把本机结果外推为实体比赛机、真实学校网络或真实教学成效。

### 48. 课堂“启动成功”状态与长期归档的一致性

- 前端的开课按钮只有在教师后续能查看课堂报告、历史与审计证据时，才可以把操作称为“启动成功”。静态追踪显示 `classroom_sessions` 只承载短期运行时，而报告与历史依赖长期 `lessons` 归档；旧路径在后者写入失败时仍会继续启动监测、广播加入码并返回成功，运行时清理后会留下无法恢复的“幽灵课堂”。这项风险来自两类存储职责和启动时序，而非对界面外观的猜测。
- 现在课堂启动与轻量会话启动先写入短期运行时、再进入长期归档门禁。短期写入失败会立即返回具名 `503 CLASSROOM_RUNTIME_UNAVAILABLE`；长期 `lessons.create` 失败则删除刚建立的运行时并返回 `503 LESSON_ARCHIVE_UNAVAILABLE`。两者均不会启动监测或广播加入码，界面不会得到假成功。若回滚本身也失败，依旧失败关闭，并把归档异常与回滚异常仅记录在服务端结构化日志，避免将内部细节泄露给教师端。
- 四项定向单元测试覆盖运行时写失败不触发归档、归档成功、归档失败后运行时回滚、归档与回滚双失败仍失败关闭且有双错误日志。随后在锁定 Node 20.20.2 / pnpm 10.34.5 环境运行全量覆盖率：51 个测试文件、616 项通过；语句 97.04%、分支 76.70%、函数 97.32%、行 97.49%。最新密码认证生产同源 E2E 仍为 32 个界面—视口组合、0 警告、0 失败。该证据证明启动状态不会在已测持久化失败路径中误报成功；它不等同于已验证真实学校数据库故障、课堂成效或外部网络。

### 49. 课堂启动持久化 503 的教师端失败闭环

- 后端已经把短期运行时或长期归档的写入失败归类为具名 `503`，但生产态的通用请求层刻意不将服务端错误正文直接透传到浏览器。该取舍能避免把内部持久化细节泄露给教师，却曾让页面只显示泛化 Toast，教师无法从主操作区立即确认本次未建立课堂、未生成加入码、也未开放实时通道。
- `ClassroomPage` 现在在启动请求未返回 `lessonId` 时保留在原路由，显示唯一的 `role="alert"` 失败区，明确写出“没有建立课堂，未生成加入码或开放实时通道”。主操作保持可用但改名为“重新尝试启动”，以 `aria-describedby` 关联这条说明；改选模式、班级或诗篇会清除旧失败状态。页面调用会显式请求 `inline` 反馈，状态仓库的默认 Toast 仍供没有页面上下文的调用方使用，因此本页面不会让同一失败被短暂 Toast 和持久警报重复播报。该页面不渲染后端原始错误体，继续遵守前端错误脱敏边界。
- 生产同源 E2E 在隔离的密码认证服务中只将首次 `POST /api/classroom/start` 受控改为 `503 CLASSROOM_RUNTIME_UNAVAILABLE`，随后检查警报、按钮名称、可访问关联与路由仍为 `/classroom`；390×844 进一步验证警报与重试按钮均完整处于视口内、无横向溢出、主按钮至少 24×32px，且不存在重复的“开始失败”Toast。第二次请求回到真实启动契约，只有成功取得课堂 ID 才允许进入课堂。证据为 `production-e2e-latest.json` 的 `classroomStartFailureClosure`、`results.json` 的 `classroomStartFailureClosureChecked`，以及桌面/移动端 `*-classroom-start-failure-closure.png`。该夹具证明前端失败披露、无假导航、非重复反馈、响应式几何与重试语义，不冒充真实学校数据库故障、课堂数据或教学成效。

### 50. 批改前后对比的状态新鲜度、可控动画与移动端保底

- `ShowcaseCards` 会在“上传 → 识别 → 批改”同一 `batchId` 内逐步形成对比卡。源码追踪和生产同源受控流程都复现了一个真实的缓存错误：三个派生查询只将 `batchId` 作为 query key，同时配置了 60 秒 `staleTime`。上传阶段先缓存“尚不足两阶段，暂无对比数据”的空结果后，后续识别或批改虽写入 Zustand 真相源，却不会让同键查询重新执行，导致应已可见的 CardSwap 在最长 60 秒内仍为空。该结论来自实际浏览器回归最初无法定位轮播容器及其后对 key/状态流的追踪，不是由静态样式猜测。
- 三个展示查询现各自使用与可见状态同步的本地指纹：文件、识别、批改、汇总或阶段任一变化都会派生新 key，因而立即重新从 Zustand 读取；指纹只进入内存 query key，不把学生答题原文或教师反馈直接暴露为 key。无真实同作业的两阶段配对时仍保持空态，未加入演示对比卡来“补齐”界面。
- 自动轮播不再把“减弱动态”误解为“播放得慢一些”：评分页的 CardSwap 已改为独立状态机实现，系统偏好为 reduce 时同时取消轮换定时器并冻结 CSS 位姿，按钮具名说明“已按系统减弱动态偏好静止显示”。普通偏好下，教师有原生、具名的暂停/继续按钮与 `aria-pressed` 状态；悬停和卡片内非控制器焦点仅作为渐进增强。无业务点击能力的展示卡不再伪装为按钮或 pointer 光标。移动端删除整体 scale 降级，改由容器宽度收缩，避免焦点环和暂停命中区被缩到不可用。
- 生产同源 E2E 在隔离受控的上传、识别、批改链路后，验证对比轮播确实从空态重派生；检查非交互卡的语义/光标、悬停冻结、教师点击暂停、550ms 内卡片 transform 不变化、Space 恢复、运行中切换 `prefers-reduced-motion` 后静止与披露，以及 390×844 下控制器完整可见、至少 24px 且页面无横向溢出。截图：`frontend/e2e-screenshots/regression/mobile-grading-card-swap-motion-control.png`。该夹具证明前端状态、动画、无障碍和几何契约，不代表学生作品、OCR、批改结论、模型质量或教学成效。
